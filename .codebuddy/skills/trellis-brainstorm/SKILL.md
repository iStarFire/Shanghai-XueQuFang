# Trellis Brainstorm

## 不可协商的规划契约

「做吧」「开始吧」**不是**离开规划阶段的许可。同意建任务也**不是**同意开始执行。

任何非平凡任务，在开始执行之前，用户必须在初次请求之后至少回复过一次。
若无需澄清，那次回复必须是对最终规划摘要的明确批准。

只要还有用户掌握的产品/范围/口径/风险/验收决定未解决，
本轮就以**恰好一个问题**结束。不要修改数据文件、不要派发执行、不要运行 `task.py start`。

## 不可协商的证据规则

**能通过检查现有材料回答的问题，就去检查，不要问用户。**

必做。提问前先确认答案是否已存在于 `data/`、`.trellis/spec/`、`来源.md`、
既有检索文件、任务历史中。

不要请用户确认仓库能回答的事实。只问：分析意图、口径取舍、范围边界、
可接受的不确定性，以及检查后仍然模糊的决定。

**本地证据能确立的是「现状与约束」，不能确立「用户想要什么」。**
既有做法是选项与建议依据，不是决定。

---

在 Phase 1 规划阶段使用本 skill，把用户请求变成清晰的需求与规划产物。

## 前置条件

仅在取得建任务同意后使用。

若尚无任务：

```bash
TASK_DIR=$(python3 ./.trellis/scripts/task.py create "<short task title>" --description "<one-line summary>" --slug <slug>)
```

标题与 `--description` 都不能为空。slug 不带日期前缀，`task.py create` 会自动加 `MM-DD-`。

`task.py create` 会生成默认 `prd.md`。提问前先把当前理解写进该文件。

## 规划流程

1. 把用户请求与已知事实写进 `prd.md`
2. 提问前先检查证据：
   - `data/<行政区>/` 下已有数据与 `来源.md`
   - `prd.md` / `design.md`、既有规范与思考指南
   - 相关任务、`research/` 文件与会话历史
   - 外部资料（官方政策、招生公告、平台数据）——必要时派发检索代理
3. 把发现分成四类：
   - 已确认事实
   - 仍需用户给出的分析意图
   - 仍需用户给出的范围/口径/风险决定
   - 可能超出范围的事项
4. 若仍有用户掌握的决定，问**唯一一个**最高价值的问题，
   附上你的推荐与取舍，然后停止。同一轮不要做任何执行工作。
5. 每次得到答复后：更新 `prd.md`，重算决定清单，回到第 2 步
6. 无剩余用户决定时，为复杂任务创建/更新 `design.md` 与 `implement.md`
7. 执行下面的「需求收敛门禁」，再做「PRD 收敛整理」
8. 呈现最终规划摘要并停止。同一轮不要运行 `task.py start` 或改数据
9. 只有后续消息明确批准最新规划摘要，才授权 `task.py start` 与执行。
   若批准后产物发生实质变化，重新走一遍最终评审

不要发明项目专属的产品/规范层级。项目已有规范结构（`spec/data`、`spec/quality`、`spec/analysis`、`spec/guides`）就直接用。

## 提问规则

每条消息只问一个问题。

每个问题必须包含：

- 需要决定什么
- 为什么这个决定重要
- 你推荐的答案
- 用户选择不同方案时的代价

不要问流程性问题（要不要去检索、要不要继续 brainstorm）。直接做证据工作。
只在剩余问题是分析意图、口径取舍、范围边界或风险容忍度时才问用户。

推荐不等于默认选择。不要因为用户说了「开始做」就替用户拍板。

不要制造无意义的澄清问题。若请求与现有证据已能解决全部决定，
直接进入最终规划摘要 —— 那仍然需要后续的明确批准。

最终评审是必需的阶段转换门禁，不是被禁止的流程性问题。
建任务同意、最初的需求描述、以及在最新摘要之前给出的批准，都不满足该门禁。

## 思考框架：第一性原理

当需求模糊、方案显得过度设计、或你正准备「因为大家都这么做」而增加复杂度时，
先分解到基本事实，再向上推理。

### 第 1 步：重述问题

剥掉实现细节，压成一句话。

> 差：「我想做一个徐汇学区房溢价分析看板」
> 好：「我想知道对口某小学是否真的让周边房价更高」

### 第 2 步：列出基本事实

哪些是绝对为真的（而非习惯或惯例）？

| 类别 | 示例 |
|------|------|
| **制度约束** | 划片范围以当年官方公告为准；公办入学与房产/户籍绑定 |
| **数据约束** | 官方只公布名录与划片，不公布成交价；平台价存在口径差异 |
| **方法约束** | 相关不等于因果；样本需覆盖高低价段 |
| **用户需求** | 「我需要在 X 时间内得到可信的方向性判断」 |

### 第 3 步：质疑假设

对当前计划的每个组成部分：

- **是事实还是习惯？** 「必须用成交价」——为什么？挂牌价能否作为方向性参考（并标注）？
- **去掉它会怎样？** 如果什么都不坏，那就是多余的
- **在解决真问题还是症状？** 追溯因果链
- **谁从这个复杂度受益？** 如果「没人」，就简化

### 第 4 步：从基本事实往上搭

1. 从满足所有基本事实的**最小可用路径**开始
2. 只在某条基本事实明确要求时才增加复杂度
3. 每增加一项都要回答：「哪条基本事实要求它？」

### 第 5 步：验证

- 方案是否回答了最初的问题？
- 哪些假设需要验证？（数据可得性、口径一致性、样本量）
- 最小验证实验是什么？

## 需求收敛门禁

最终评审前，逐项确认：

- [ ] 要回答的问题与分析价值是明确的
- [ ] **数据范围明确**：行政区、时间窗、学段、房屋类型
- [ ] 范围内 / 范围外行为明确
- [ ] 验收标准描述的是**可观测的结果**（例如「给出 12 个对口小区的价格对比表，并说明口径与局限」）
- [ ] 用户掌握的口径、范围与风险决定已解决
- [ ] **数据正确性校验标准已明确**（2.2 用什么判定「数据可信」）
- [ ] **结论可靠性验证标准已明确**（2.4 用什么判定「结论站得住」）
- [ ] 阻塞性未决问题已清空
- [ ] 数据可得性等未知项已被检索，或明确延后且不改变本次范围

轻量任务可以省略 `design.md` 与 `implement.md`；但不得跳过证据检查、
需求收敛、最终评审与新的执行批准。

最终规划摘要必须包含：目标、范围内、范围外、验收标准、关键决定、
风险或延后项、产物状态。

## 产物规则

`prd.md` 记录需求与验收：

- 目标与分析价值
- 已确认事实
- 数据范围（行政区 / 时间窗 / 学段 / 类型）
- 需求与验收标准
- 范围外
- 数据正确性校验标准（2.2）
- 结论可靠性验证标准（2.4）
- 仍阻塞规划的未决问题

`design.md` 记录复杂任务的分析设计：

- 数据来源清单与可得性
- 字段定义与口径
- 指标定义与计算方式
- 对比基准
- 偏差来源与局限声明
- 回滚/中止条件（例如数据不可得时如何处理）

`implement.md` 记录复杂任务的执行计划：

- 有序执行清单：采集 → 数据校验 → 分析 → 结论验证
- 每步的校验/验证方法与判定标准
- 风险点与回滚点
- `task.py start` 之前的检查项

轻量任务可以只有 `prd.md`。复杂任务在 `task.py start` 前必须具备三份产物。

`implement.md` 不能替代 `implement.jsonl`。子代理调度模式下，
`implement.jsonl` 与 `check.jsonl` 必须各含至少一条真实条目，
空的或只剩旧版 `_example` 占位行的清单都不算就绪。

## PRD 收敛整理

宣布规划就绪或运行 `task.py start` 之前，对照上面的产物结构重写一遍 `prd.md`。
这不是可选的清理，而是最终规划门禁。

整理必须无损：

- 重复事实合并进一个权威章节
- 把临时章节（`我已知的`、`假设`、已解决的 `未决问题`）并入目标、背景、需求或验收标准
- 删除已解决的未决问题，不要留下空章节或已答问题
- 描述同一件事的需求列表合并；每个缺陷的严重度、证据、`文件:行` 锚点保留在对应需求上
- 保留每一个 `文件:行` 锚点、决定、约束、需求编号与验收映射
- 仍有阻塞性未决问题时，不得进入最终评审

整理完毕后通读一遍 `prd.md`，确认除新增信息外没有跨章节重复的事实。

## 质量标准

宣布规划就绪之前：

- [ ] `prd.md` 含可检验的验收标准
- [ ] `prd.md` 已通过收敛整理：无临时章节残留、无跨章节重复、无锚点/决定/验收映射丢失
- [ ] **数据正确性校验标准与结论可靠性验证标准已写入产物**
- [ ] 现有材料可回答的问题已通过检查解决
- [ ] 阻塞性未决问题为空
- [ ] 复杂任务具备 `design.md` 与 `implement.md`
- [ ] 子代理调度任务的 `implement.jsonl` 与 `check.jsonl` 均有真实条目
- [ ] 最新规划摘要已呈现给用户
- [ ] 用户在后续消息中明确批准了该摘要

不要因为用户最初说了「开始做」就开始执行。
