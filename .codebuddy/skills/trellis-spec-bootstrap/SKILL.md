# Trellis Spec Bootstrap

用本 skill 从项目现状创建或刷新 `.trellis/spec/` 规范。
由一个能力足够的代理负责完整闭环：盘点数据与来源、划定规范边界、写文档、验证结果。

本项目是**上海学区房数据分析项目**，规范面向**数据与分析**，不面向代码。

## 工作流

1. 确认 Trellis 已初始化，检查当前 `.trellis/spec/` 树
2. 盘点项目现状（这是规范的事实来源）：
   - `data/` 下有哪些行政区、哪些主题（`学校` / `小区` / `规划`）、哪些文件
   - 每个目录的 `来源.md` 记录了什么来源、口径、已知缺陷
   - 任务目录 `.trellis/tasks/` 中已产生的口径决定、校验记录、结论验证记录
   - `README.md`、既有规范与思考指南
3. 只在符合实际情况时按分层拆分规范：
   - `data/` —— 数据来源、目录结构、命名、字段与口径
   - `quality/` —— 数据正确性校验维度与判定标准
   - `analysis/` —— 分析方法、结论可靠性验证
   - `guides/` —— 跨领域思考清单
4. 用项目中的真实内容填充或重塑规范文件：真实字段名、真实枚举取值、
   真实来源与文号、真实的坑、真实的反例
5. 验证最终规范内部一致、无模板占位文本

## 操作规则

- 把模板当起点而非契约。项目需要时，删除、改名、拆分、新增规范文件
- 优先写**有出处**的规则。每条重要约定都应指向真实文件、真实来源或反复出现的模式
- 默认单代理闭环。可选的辅助代理是实现细节，不是必需依赖
- 不要写平台专属说明，除非目标项目已统一使用该平台
- 不要在 `.trellis/spec/` 留下占位文本、空标题或照抄的模板样板
- 区分「规范」与「指南」：规范写「怎么做才算对」（字段定义、判定标准、失败矩阵），
  指南写「动手前该想什么」（检查清单）

## 完成标准

- [ ] `.trellis/spec/` 描述的是项目**当前真实状态**，而非理想状态
- [ ] 每个规范分层都有可操作的判定标准与真实示例
- [ ] 数据校验规范包含七个维度与具体判定阈值
- [ ] 结论验证规范包含九个维度与具体验证方法
- [ ] 不适用的模板章节已被删除
- [ ] 各层 `index.md` 与最终规范文件集一致
- [ ] 规范中引用的数据文件路径、字段名、来源均真实存在
- [ ] 无占位文本、空标题、照抄样板
