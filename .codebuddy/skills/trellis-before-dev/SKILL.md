description: "在工作流 2.1 / 2.3 开始前，发现并注入 .trellis/spec/ 下的项目规范（数据规范、数据校验规范、分析与结论验证规范）以及共享思考指南。适用于开始新的数据采集/整理/分析工作前、切换到新的行政区或主题、或需要刷新项目约定时。"
---

开始工作前，先读取相关项目规范。

按顺序执行：

1. **读取当前任务产物**：
   - `prd.md` — 要回答的问题、数据范围、验收标准
   - `design.md`（如有）— 分析设计：口径、指标定义、对比基准、局限
   - `implement.md`（如有）— 执行顺序与判定标准

2. **发现可用的规范分层**：
   ```bash
   python3 ./.trellis/scripts/get_context.py --mode packages
   ```

3. **判断哪些规范适用**，依据：
   - 本次动作属于哪一类：数据采集/整理（`spec/data/`）、数据校验（`spec/quality/`）、
     分析（`spec/analysis/`）
   - 涉及哪个行政区、哪个主题（学校 / 小区 / 规划）
   - 任务产物中引用的规范或检索文件路径

4. **读取对应规范入口**：
   ```bash
   cat .trellis/spec/<layer>/index.md
   ```
   按其中的 **开工前检查清单（Pre-Development Checklist）** 逐项确认。

5. **读取入口指向的具体规范文件**。入口文件本身不是目标 —— 它指向真正的规则文件
   （`directory-structure.md`、`source-registry.md`、`field-conventions.md`、
   `data-validation.md`、`method-guidelines.md`、`conclusion-verification.md`）。
   读这些文件，而不是只看入口。

6. **始终读取共享思考指南**：
   ```bash
   cat .trellis/spec/guides/index.md
   ```

7. **非平凡任务，动手前先声明变更边界。** 「非平凡」指：涉及多个文件、跨行政区/跨主题、
   新增或修改字段口径、改动既有数据、或复用你刚写过的分析。
   写下来：
   - 现状与目标之间最小的差距是什么
   - 这个差距实际存在于哪一层（数据层？口径层？分析层？）—— 不要挑最容易下手的地方改
   - 预计要改哪些文件，每个为什么必要
   - 本次**不做**什么
   - 若需要重构既有数据/口径，如何证明没有改变原有含义

   小而明确的工作不需要这一步 —— 直接做。

   若发现真实范围明显大于上述边界，先说清并说明原因再继续。不要自行扩大范围。

8. **明确两条门禁的判定标准**（本项目强制）：
   - 2.2 数据正确性校验：哪些维度、用什么方法、什么情况判为不通过
   - 2.4 结论可靠性验证：哪些维度、如何独立重算、如何检验稳健性

9. 理解并遵循上述规范后，再进入执行计划。

**这一步是强制的** —— 在采集或分析任何数据之前必须完成。
