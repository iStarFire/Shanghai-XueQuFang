# 数据校验与结论验证

本 skill 覆盖工作流 **2.2 数据正确性校验** 与 **2.4 结论可靠性验证**。

核心要求：**校验必须能失败**。一个永远通过的校验等于没有校验。

---

## 第 1 步：圈定校验对象

```bash
git status --porcelain
git diff --name-only
```

分类：

- `data/**` → 走 2.2 数据正确性校验
- `{TASK_DIR}/analysis/**` → 走 2.4 结论可靠性验证

## 第 2 步：读任务产物与判定依据

按顺序读：

- `prd.md`
- `design.md`（如有）
- `implement.md`（如有）

```bash
python3 ./.trellis/scripts/get_context.py --mode packages
cat .trellis/spec/quality/index.md
cat .trellis/spec/analysis/index.md
```

再读入口指向的具体规范文件（`data-validation.md`、`conclusion-verification.md`）——
入口是指针，不是目标。

## 第 3 步：证明校验方法有效

构造或注入若干「语义上明显错误」的样例，确认你的校验能捕获它们：

- 数值越界（单价为负、建成年代 1800）
- 枚举越界（学段写「幼儿园」）
- 重复记录（同一小区出现两次）
- 时点错位（用了上一学年的划片范围）

**捕获不到的维度 → 该方法不合格**，必须换方法并在记录中说明。
不可省略此步：未经检验的校验等于未校验。

## 第 4 步：逐维度执行

### 2.2 数据正确性校验（七个维度）

完整性 · 唯一性 · 值域 · 一致性 · 时效性 · 可追溯性 · 口径一致性

### 2.4 结论可靠性验证（九个维度）

计算复核 · 口径一致 · 数据链路 · 样本代表性 · 对比基准 ·
因果警惕 · 反向证据 · 稳健性 · 局限声明

每个维度都必须给出：**结果 + 证据（文件:行 + 具体值）+ 处置**。

关键方法（必须真做）：

- **独立重算** —— 不复用分析过程的中间结果（循环验证无效）
- **抽样回源** —— 从数字走到数据文件 → 字段 → `来源.md` → 原始来源
- **敏感性测试** —— 换口径或剔除极端值重算，看结论是否翻转
- **红队提问** —— 「如果我不同意，我拿哪条数据反驳？」
- **抽样覆盖首、中、尾与已知异常行** —— 不要只挑规整样本

## 第 5 步：自修复与复核

- 机械问题（格式、命名不统一、枚举越界、名称别名未统一）→ 直接修 → **重新校验受影响项**
- 判断问题（口径变更、结论表述取舍、样本取舍）→ 记录证据与建议，交主会话决定，
  不要静默改写
- 「未发现问题」≠「数据无误」：前者是观测，后者需要证据

## 第 6 步：落盘与门禁结论

- 2.2 → `{TASK_DIR}/validation/data-validation.md`
- 2.4 → `{TASK_DIR}/validation/conclusion-review.md`

格式见对应规范文件。必须明确写出：

- 未处置的不通过项数量
- **门禁结论：通过 / 不通过（需回到 2.1 或 2.3）**
- 残余风险（无法消除的不确定性）

## 门禁规则（不可绕过）

| 情况 | 处置 |
|------|------|
| 存在未处置的不通过项 | 回到 2.1 / 2.3，禁止推进 |
| 校验记录缺失或只有结论没有证据 | 视为未校验，重做 |
| 用户要求带缺陷继续 | 必须在记录中写入用户的降级确认，并写入结论局限声明 |
| 核心结论计算不一致 / 数据链路断裂 / 样本明显不足 / 口径偷换 | 2.4 判为不通过，必须回到 2.3 修正后重新验证 |

---

## 反模式（出现即判为未校验）

- 「整体看起来正常」—— 没有逐维度结论
- 只有通过/不通过，没有样本证据
- 用校验脚本的退出码代替结论，而脚本从未被验证过能捕获错误
- 修复后不重新校验，沿用旧结论
- 把「本次未发现问题」写成「数据无误」
- 抽样只挑最规整的几条
- 门禁不通过却为了让流程往前走而写成「通过」
