## 开工前检查清单（Pre-Development Checklist）

开始 2.3 之前，确认：

- [ ] 依赖的数据已**通过 2.2 校验**（`validation/data-validation.md` 门禁结论为「通过」或已显式降级）
- [ ] 已读取 `design.md` 中的口径、指标定义、对比基准
- [ ] 已明确本次要回答的问题与「什么样的结果算回答了问题」
- [ ] 已明确**反向证据**要去找什么（哪些数据出现就意味着结论不成立）
- [ ] 已确定分析与验证记录要写入 `{TASK_DIR}/analysis/` 与 `{TASK_DIR}/validation/`

---

## 质量校验（Quality Check）

2.3 与 2.4 完成时，逐项确认：

- [ ] 每个数字都能回溯到具体数据文件与字段
- [ ] 每条结论都附了支撑数据与样本量
- [ ] 事实描述与推断判断**显式分离**
- [ ] 主动写出了反向证据与异常个案
- [ ] 局限与不确定性已声明（数据缺口、政策变动、样本偏差）
- [ ] 关键指标已被独立重算并一致
- [ ] 验证记录已落盘到 `{TASK_DIR}/validation/conclusion-review.md`
- [ ] 未通过项已回到 2.3 修正并重新验证

---

## 门禁规则（不可绕过）

| 情况 | 处置 |
|------|------|
| 核心结论计算复核不一致 | 回到 2.3 修正，重新执行 2.4 |
| 数字无法回溯到数据文件/字段 | 回到 2.3 补齐链路 |
| 样本量明显不足或只覆盖少数对象 | 回到 2.3 扩充样本，或在结论中显著标注为「初步」 |
| 结论依赖的相关性被表述为因果 | 修正表述，或补充因果检验 |
| 存在被忽略的反向证据 | 回到 2.3 纳入分析 |
| 未验证但需要对外输出 | 必须在结论中显著标注「未经可靠性验证」，并说明风险 |
