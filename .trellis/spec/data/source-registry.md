# 来源登记规范（来源.md）

> **可追溯性是数据可信的前提。** 没有来源登记的数据，一律视为未校验数据，
> 不得用于任何结论。

---

## 要求

每一个 `data/<行政区>/<主题>/` 目录下**必须**有一个 `来源.md`，
登记该目录内**所有**数据文件的来源与口径。

新增或修改数据文件时，必须在同一提交中更新 `来源.md`。

---

## 登记表格式

`来源.md` 采用如下结构：

```markdown
# <行政区> - <主题> 数据来源登记

## 数据文件清单

| 文件 | 来源 | 发布主体 | 发布时间 | 采集时间 | 采集人 | 口径说明 | 已知缺陷 |
|------|------|----------|----------|----------|--------|----------|----------|
| `小学名录-公办-2026.csv` | <URL 或文件路径> | 徐汇区教育局 | 2026-04-15 | 2026-09-30 | ivan | 仅公办小学，含九年一贯制小学部 | 3 所学校地址缺失 |
| ... | | | | | | | |

## 字段口径说明

### `unit_price`（单价）

- 原始口径：<来源文件中的表述>
- 本项目口径：<建筑面积单价，单位 元/㎡>
- 换算方式：<如有换算，写清公式>

## 修订记录

| 日期 | 修订内容 | 修订人 |
|------|----------|--------|
| 2026-09-30 | 首次登记 | ivan |
```

---

## 硬性要求

1. **来源必须具体**：写 URL 或原始文件路径，不要写「网上查到」「教育局网站」这类无法定位的描述。
2. **发布主体与发布时间必填**：政策类、划片类数据缺发布时间视为不可用。
3. **口径说明必填**：同一个指标在不同来源口径不同时，**分开登记、分开存放**，
   不要合并成一份「看起来统一」的数据。
4. **已知缺陷必须写**：缺字段、样本偏少、时点偏旧、来源非官方 —— 有什么写什么。
   缺陷栏留空表示「未发现问题」，而不是「没检查」。
5. **非官方来源必须标注**：自媒体、中介平台、论坛信息必须标为「非官方」，
   且在结论中不得作为唯一依据。

---

## 检查点（工作流 2.2 会复核）

- [ ] 目录下每个数据文件都能在 `来源.md` 中找到一行
- [ ] 每行的「来源」「发布主体」「发布时间」「采集时间」「采集人」均非空
- [ ] 口径说明与实际字段内容一致（例如声明是成交价，数据里却是挂牌价）
- [ ] 已知缺陷栏与数据的真实状态一致（抽查若干条记录验证）
