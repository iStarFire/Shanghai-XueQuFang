# 数据校验规范

> 本文是工作流 2.2 的执行标准。核心要求：**校验必须能失败**。
> 一个永远通过的校验等于没有校验。

---

## 一、七个校验维度

### 1. 完整性（Completeness）

检查：必填字段是否缺失、记录条数是否符合预期。

方法：

- 逐字段统计空值率；必填字段空值率 > 0 即为不通过
- 与来源声明的条数对比（如官方名录有 47 所小学，文件里只有 45 行 → 说明缺 2 所，必须写明是哪 2 所）
- 检查文件是否被截断（末行是否完整）

不通过判定：必填字段有缺失，或条数少于来源声明且未说明原因。

### 2. 唯一性（Uniqueness）

检查：主键/自然键是否重复。

方法：

- 学校：`school_name` + 校区 唯一
- 小区：`community_name` + `district` 唯一（注意别名，见 `field-conventions.md`）
- 规划：`doc_number`（无文号时用 `doc_title` + `publish_date`）唯一

不通过判定：出现重复记录，且无法解释为「同名校区的不同实体」或「不同来源的同一实体」。

### 3. 值域（Domain）

检查：数值范围与枚举取值是否合法。

方法（示例阈值，可按行政区调整）：

- `built_year` ∈ [1900, 当前年]
- `unit_price_cny_per_sqm` ∈ (0, 500000]
- `enrollment_plan` ∈ [0, 5000]
- `school_type` / `ownership` / `price_type` / `property_type` / `category` / `status` 必须命中枚举集合
- 日期格式符合 `YYYY-MM-DD` / `YYYY-MM`

不通过判定：出现越界值或枚举外的取值。

### 4. 一致性（Consistency）

检查：同一实体在不同文件/字段间是否自相矛盾。

方法：

- 同一小区在 `小区` 与 `规划` 目录中的行政区/地址是否一致
- `school_name` 命名是否与 `对口划片` 文件中引用的名称一致
- `building_count` 与 `household_count` 是否量级合理
- 同一时点同一小区的单价与总价/面积是否自洽

不通过判定：存在矛盾且没有解释性说明（例如「来源不同口径不同」需在 `来源.md` 中登记）。

### 5. 时效性（Freshness）

检查：数据时点是否在声明的有效期内。

方法：

- 划片/招生数据：必须对应最近一个已公布的招生年度；过期即为不通过
- 价格数据：`price_month` 距当前不超过约定窗口（默认 6 个月）
- 规划数据：`status` 为 `已废止` 的不得作为当前依据

不通过判定：数据超出有效期且未标注「历史数据」。

### 6. 可追溯性（Traceability）

检查：每条记录能否定位到来源与采集时间。

方法：

- 每个数据文件在 `来源.md` 中有登记行
- 登记行的来源、发布主体、发布时间、采集时间、采集人非空
- 抽查 3~5 条记录，回到来源核对是否一致（**必须真做，不能只看登记表**）
- **`source_page` 必须真能被用来定位一次**：打开该文件该页，
  确认目标行就在那里。只检查「字段非空」不算完成。

**（本节专项）`source_page` 的两个必查点**：

1. **必须写「真实页码」，不是「PDF 对象号」**。
   对象号长得也像页码，且不报错、不越界，值域检查根本发现不了
   （本项目实测：某单页 PDF 的 `source_page` 写成 `6`，实为对象号）。
   判定：`source_page` 最大值不得超过该 PDF 的实际页数。
2. **两表同名同义**：同一项目内该列必须处处同义，不得一个文件写页码、
   另一个文件写对象号或表格编号。
   判定：跨表抽查同一 `source_page` 值，语义必须一致。

不通过判定：文件未登记；抽查与来源不符；`source_page` 超出实际页数；
或跨表语义不一致。

### 7. 口径一致性（Caliber）

检查：是否与 `design.md` 定义的口径一致。

方法：

- 逐字段核对：字段含义、单位、计算方式是否与 `design.md` 一致
- 特别检查易混项：挂牌价/成交价、建筑面积/使用面积、居委/小区/门牌划片
- **逐列对照字段清单**：把 `design.md` 的字段表与 CSV 的实际表头**并排列出**，
  逐列打勾。**`design.md` 定义了字段 ≠ CSV 已经含该字段**——
  只检查「有没有值」会漏掉整列缺失（本项目实测：一份长表少了 5 个
  `design.md` 已定义的列，因为生成脚本从未写出它们，而校验只看了「有没有值」）。

不通过判定：实际口径与 `design.md` 不一致且未修订 `design.md`；
或 `design.md` 字段表与 CSV 表头**存在任何差异**（多列、少列、改名、换序）。

## 三、反模式（出现即判为未校验）

- 「数据整体看起来正常」——没有逐维度结论
- 只有「通过/不通过」，没有样本证据（行号、具体值）
- 用校验脚本的退出码代替结论，但脚本从未被验证过能捕获错误
- 修复数据后不重新校验，直接沿用旧结论
- 把「本次未发现问题」写成「数据无误」——前者是观测，后者是需要证据的断言
- 抽样时只挑最规整的几条（应覆盖首、中、尾与已知异常行）
- **把「值对得上」当成「能定位」**：抽查只比对数值是否相等，不打开
  `source_doc` + `source_page` 看那一行是否真在那里。
  数值相同与页数指得准是**两件事**，必须分别验。
- **图像回源抽查时只按 y 坐标裁剪**，不把**行标识列**（学校编号/序号）
  拼进裁剪图。行高估算差几像素就会整体错位一行，而错位后「每行都对得上」
  的假象极难自查——会据此误报「CSV 多值/少值」。
- **在报告里写「已填 / 已校验 / 已核对」但从未真做过一次**。
  这类自述必须能指出**具体动作与它的输出**，否则视为未做。

## 四、常见真实陷阱（本项目已遇到/易遇到）

1. **同名不同校**：不同区存在同名的「实验小学」，跨区合并统计会导致严重错误。
2. **政策时点错位**：用 2025 年划片范围分析 2026 年房价，结论无效。
3. **居委划片无法落到小区**：划片按居委时，需要居委-小区映射表，直接按小区名匹配会漏配。
4. **挂牌价虚高**：挂牌价普遍高于成交价，用挂牌价算溢价会高估。
5. **商住混入**：商住楼盘不能入学，混入会拉低「学区溢价」的估算。
6. **规划未落地**：把征求意见稿当既成事实，导致高估未来溢价。
7. **同编号改名（本项目已遇到）**：同一所学校编号在不同年份可能用完全不同的名称
   （实测：「上海市长桥中学」→「上海市徐汇区教育学院附属实验中学南部分校」）。
   - 若不按**编号**归并 → 会被当成两所学校；
   - 若归并后**取首次出现的名字**作显示名 → 已改名的学校会一直顶着旧名，
     而旧名与新名差异越大，越容易被读者误认为**两所不相干的学校**。
   - 判定：同一编号在跨年汇总表里**只能占一行**，显示名取**最新年份**的写法，
     历年其他写法单独记一列。
8. **同编号内的两个实体名极其相似（本项目已遇到）**：`041327`「上海市徐汇区教育学院
   附属实验中学」与 `041328`「…中学**南部分校**」只差两个字，但**是两所学校**。
   另有「上海市南洋初级中学」（初中 `041316`）与「上海市南洋中学」（高中 `043015`），
   **跨学段**、绝不能合并。判定：凡校名互为前缀/后缀的，**必须回原始 PDF 核对编号**，
   不得凭名称相似度推断同一性。
9. **`source_page` 写成 PDF 对象号**：对象号同样是数字，值域检查不会报错
   （实测：单页 PDF 写成 `6`）。判定：`source_page` 不得超过该 PDF 实际页数。
10. **PDF 无文本层只能读图**：扫描件（整页 JPEG）用文本提取会得到空结果，
    容易被误判为「文件损坏」。判定：先检查页面是否为图片对象，
    是则必须渲染读图，且**不能只读一遍**（自读多遍无法互相印证时应标记「未转录」，
    而不是把「未见异常」当成「已正确」）。
11. **`/Rotate 90` 的页面渲染成全白**：部分生成器（如 Aspose）会给页面加旋转标记，
    某些渲染器（如 macOS `sips`）会输出**全白图**，容易被误判为坏文件。
    判定：渲染后先检查图片是否接近纯白，是则换渲染器。

12. **PDF 表格抽取禁止「同一行」假设**：官方 PDF 里**名称通常垂直居中、数字贴基线**，
    同一逻辑记录的名称与数字可能落在相差 3px 的两个文本行。
    - **反例**（2026-10 黄浦，5 份 PDF）：按「名称 + 数字同行」抽取，763 行 vs 实际 952 行，
      **随机漏抽 189 行（20%）**。2023 最甚：88/168，4 所初中一条不剩。
    **随机漏抽最危险**：每所学校仍都有几行数据，CSV「看起来完整」，不会触发任何异常告警。
    - **判定**：名称配对用「同页最近 y（容差 ±8px）」，不要求同行；
      名称**按内容**匹配已知名称池（初中池 + 高中全称池），不依赖 x 列边界——
      长名称会左移越过边界（「上海市格致中学（奉贤校区）」14 字 ≈ 155px 宽）。
    - **名称换行**：2 行校名会被中间的高中名隔开，按 (y,x) 拼成串会不连续而匹配不到。
      先按 **x 起点最大间隙**分成两组，组内再按 y 顺序拼接。

13. **抽取完整性必须用「记录数」判定，不能用「有无数据」判定**：
    - 要求 `每年记录数 == 独立第二实现重数`（换一种分桶粒度或另一种解析入口重算），
      不一致即失败。单实现自证「记录数 == 自己的输出长度」是同义反复。
    - 要求 **名称 100% 配上**，且「分数线 ⊇ 计划表有名额的组合」；
      出现缺口必须逐条查因，不得直接归为「官方数据不全」。
    - 差额必须能说清去向：新增/缺失各多少条、是否有同键值冲突。
      **同键值冲突（同一 初中×高中 分数不同）是最严重的信号**，
      须查明是旧抽取错还是新抽取错，**不得直接采用新值**。
    - 门禁的基线必须是**重抽前的原始文件且不可被覆盖**。踩过的坑：对账脚本把
      「写盘前的备份」当基线，而该文件在第二次写盘时已被自己覆盖，
      于是「自己比自己」恒为差异 0，对账形同虚设。基线应取自版本库。

14. **PDF 表格的列角色必须按取值特征判定，不靠表头文字、也不靠「取前 N 簇」**：
    - 表头可能被合并成一串（黄浦 2022 的科目表头是「语数外数学语文综合测试」单段），
      或被水印遮挡（2025/2026）；固定 x 边界只在某一年成立。
    - **列数本身会随年份变**：黄浦 2022/2023/2024 是 5 列（录取最低分 + 4 科目），
      **2025/2026 是 6 列**（多一个「综合素质评价」，取值恒为 50）。
      若固定取 5 簇，该列会被当成语数外 → **后面所有科目列右移一位，且最后一列整列丢失**。
    - **判定**：先用取值特征识别特殊列（恒为 50 → 综合素质评价；取值 650–770 → 录取最低分），
      剩余列按 x 升序对应剩余字段；列数与预期不符时**直接失败，不猜**。
    - 列数变化的年份必须在 CSV 的 `note` 列写明依据，并按年断言（不可用全局规则）。
