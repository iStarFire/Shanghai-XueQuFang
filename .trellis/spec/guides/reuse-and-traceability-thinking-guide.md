# 复用与可追溯思考指南

> **目的**：同一口径只允许有一种定义；结论中的每个数字都必须能走回数据。

---

## 两个核心问题

1. **同一概念是否在多处被各自定义？** → 口径漂移
2. **结论中的数字能否走回原始数据？** → 可追溯性

前者导致「同一指标两个值」，后者导致「结论无法被检验」。

---

## 一、新建之前先查

```bash
# 按内容搜索
grep -rn "关键词" data/ .trellis/spec/

# 按文件名搜索
find data/ -iname "*关键词*"
```

| 问题 | 如果是 |
|------|--------|
| 目录里已经有同类数据文件？ | 复用或扩展它，不要新建平行文件 |
| 该指标已在别处定义过？ | 复用同一定义，不要重新解释 |
| 我是不是在复制一份数据并改几个值？ | **停** —— 记录差异，或把差异做成显式字段 |
| 我在改字段名/口径？ | 先全局搜索该名字与口径的所有出现位置 |

---

## 二、口径的单一真源

- 每个指标的**定义**只在 `.trellis/spec/data/field-conventions.md` 与对应
  `来源.md` 的「字段口径说明」里出现
- 每个指标的**取值**只在 `data/` 下的一个文件里出现（同一实体同一时点）
- 分析文档里不得重新定义指标，只能引用

**反例**：`analysis/report.md` 里写「本文的溢价率定义为 A」，
而 `design.md` 里定义是 B —— 这就是两处定义，必然漂移。

---

## 三、结论的可追溯链

每条结论必须能走完这条链：

```
结论 → 指标值 → 聚合口径与筛选条件 → 关联结果 → 数据文件 → 字段 → 来源.md → 原始来源
```

**任何一环断了，结论就是不可验证的。**

自检方法：把你的结论交给一个没参与分析的人，只给他数据目录，
他能否在 15 分钟内复现出同一个数字？不能 → 链路缺失。

---

## 四、重复出现的数字

同一个数字出现在 2 处以上时：

- **坏**：两处各写一遍（一处更新后另一处就错了）
- **好**：只在一处产出，另一处引用位置（如 `analysis/metrics.md` 第 N 节）

若必须复制（例如对外报告），必须在报告中注明「数据产出位置」，
并在数据更新时回到报告同步。

---

## 五、批量修改之后

改了字段名 / 口径 / 枚举取值之后：

1. **搜索**：`grep -rn "旧值" data/ .trellis/`
2. **回溯**：所有引用它的分析文档与结论是否仍然成立？
3. **重校**：受影响的数据必须重新走 2.2 校验
4. **重验**：受影响的结论必须重新走 2.4 验证

---

## 六、提交前检查清单

- [ ] 搜索过是否已有同类数据文件与指标定义
- [ ] 没有同一口径的多份定义
- [ ] 没有同一实体同一时点的多份互相冲突的数据
- [ ] 结论中的每个数字都能走完可追溯链
- [ ] 重复出现的数字已标注产出位置
- [ ] 改动字段/口径后，受影响的数据已重新校验、结论已重新验证

---

## 七、易踩的坑

### 坑 1：平行副本悄悄分叉

目录里出现 `小区挂牌价-2026-09.csv` 和 `小区挂牌价-2026-09-修订.csv`。
两者都会有人引用，最终结果不一致。

**预防**：修订就直接改原文件；确需保留旧版就移到 `_历史/` 并在 `来源.md` 标注。

### 坑 2：指标在分析中出现第二定义

分析过程中为了「方便」临时改了分母，忘记同步 `design.md`。

**预防**：口径变更必须**先改 `design.md`**，再改分析；不允许只在分析里改。

### 坑 3：名称别名当成两个实体

「XX苑」与「XX园」被当成两个小区，统计时各占一半样本。

**预防**：建立别名映射并统一；对未匹配项输出清单人工确认。
