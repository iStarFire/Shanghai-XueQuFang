# 跨来源一致性思考指南

> **目的**：数据在来源之间、时点之间、层级之间的边界上最容易出错。
> 动手合并/汇总之前，先想清这些边界。

---

## 问题所在

**多数数据错误发生在「边界」上，而不是单个文件内部。**

常见的跨来源错误：

- A 来源的「单价」是挂牌价，B 来源是成交价，合并后算出的「均价」没有意义
- 按 `community_name` 关联两个文件，但两边小区名写法不同 → 大量静默漏配
- 用 2025 年划片范围分析 2026 年房价 → 时间错位
- 徐汇区按居委划片，普陀区按小区划片 → 跨区套用同一套匹配逻辑
- 一所学校有多个校区，对口范围不同，合并成一行后划片范围失真

---

## 动手前：画出数据流

```
官方公告/平台数据 → 采集 → 整理入库(data/) → 关联匹配 → 聚合 → 指标 → 结论
```

对每一个箭头问：

- 数据在这里是什么形态、什么口径、什么时点？
- 这里可能出什么错？
- 谁负责在这一层校验？

---

## 边界清单

| 边界 | 常见问题 |
|------|----------|
| 多来源 → 同一文件 | 口径混杂、单位不一致、时点不一致 |
| 学校 ↔ 小区 | 按名称关联漏配；按居委划片无法直接落到小区 |
| 行政区 ↔ 行政区 | 政策口径不同（划片依据、入学门槛、民办政策） |
| 时点 A ↔ 时点 B | 政策调整、口径变更、学校改名/合并 |
| 规划 ↔ 现状 | 把「征求意见稿」当既成事实；规划落地晚于发布 |
| 事实 ↔ 推断 | 把相关当因果，把单点当整体 |

---

## 定义「契约」

每引入一个新来源，先写下：

- 精确字段清单与单位
- 时点（数据本身对应哪一年/哪一月）
- 发布主体、发布时间、是否官方
- 与既有来源的口径差异（尤其价格类型、面积口径、划片依据）
- 关联键是什么（小区名？地址？居委？门牌？）

写进该目录的 `来源.md`。

## 常见错误

### 错误 1：隐式口径假设

**坏**：直接取 A 文件的 `unit_price` 和 B 文件的 `unit_price` 求平均。

**好**：先确认两者 `price_type` 与面积口径一致；不一致就分别统计并在结论中说明。

### 错误 2：按名称硬关联

**坏**：`JOIN ON community_name`。

**好**：先建别名映射表（处理「XX苑」/「XX园」/「XX小区」等写法差异），再关联；
并输出**未匹配清单**，人工确认未匹配项是「真的没有」还是「写法不同」。

### 错误 3：时点漂移

**坏**：把多个年份的价格拼成一个序列直接算增长率。

**好**：序列中每个点标注时点与当月口径；政策变动点显式标出；口径变过的段落断开处理。

### 错误 4：单层校验

**坏**：在采集层校验一次，之后所有下游都假设数据正确。

**好**：关联后重新校验关联结果（漏配率、重复匹配率），聚合后校验聚合口径
（分母是什么、排除了什么）。

### 错误 5：跨区直接套用

**坏**：在徐汇验证过的划片匹配规则，直接套用到普陀区。

**好**：每个行政区单独确认划片依据（居委 / 小区 / 门牌），分别实现并分别校验。
