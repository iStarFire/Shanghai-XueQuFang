# 思考指南（Thinking Guides）

> **目的**：在动手之前，把「没想到」提前变成「想到了」。

---

## 为什么需要思考指南

**绝大多数数据错误与结论翻车，来自「没想到」，而不是能力不足**：

- 没想到两个来源的口径不同 → 合并后结论错
- 没想到政策有时点 → 用过期划片分析当前房价
- 没想到同名不同校 → 跨区合并统计
- 没想到样本只覆盖了高端小区 → 溢价被高估
- 没想到复核者需要证据 → 结论无法被检验

这些指南帮你在**动手前**先问对问题。

## 思考触发器速查

### 什么时候要警惕跨来源问题

- [ ] 数据来自 2 个以上来源
- [ ] 要把两个文件合并/关联（尤其是按名称关联）
- [ ] 跨行政区汇总，而各区政策口径可能不同
- [ ] 跨时点比较，而中间发生过政策调整
- [ ] 划片按「居委」而数据按「小区」
- [ ] 同一指标在不同文件里字段名不同

→ 读[跨来源一致性思考指南](./data-consistency-thinking-guide.md)

### 什么时候要警惕复用与可追溯问题

- [ ] 要新建一个数据文件，而目录里似乎已有类似文件
- [ ] 要定义一个新指标（尤其是「溢价率」「涨幅」这类）
- [ ] 同一个数字在 2 处以上出现
- [ ] 你要写一条结论，但说不出它对应哪个文件的哪个字段
- [ ] 你在改字段名或口径，而其他地方也在用

→ 读[复用与可追溯思考指南](./reuse-and-traceability-thinking-guide.md)

### 复核 AI 给出的校验/验证结论时

AI 的校验与验证存在固定的假阳性/假阴性模式：

**常见的假阴性（说通过了但其实没查）**：

1. **方法未验证** —— 校验脚本从未被证明能捕获错误，却用它的「无输出」当通过
2. **循环验证** —— 用分析过程的中间结果当验证证据
3. **只查格式不查语义** —— 「字段齐全、类型正确」当「数据正确」
4. **只挑规整样本** —— 抽样时避开已知异常行

**常见的假阳性（报了问题但其实没问题）**：

1. **口径误判** —— 把「不同来源不同口径」当「数据不一致」
2. **时效误判** —— 把明确标为历史数据的旧数据当「过期数据」
3. **别名误判** —— 把同一小区的不同写法当「重复记录」

**复核规则**：每一条「通过」和「不通过」都必须先回到实际数据核对，再决定是否采纳。
对 AI 校验结论，按经验预算约 35% 的误判率。

## 修改前规则（重要）

> **改动任何字段名、口径、枚举取值之前，先搜索一遍！**

```bash
grep -rn "要改的值" data/ .trellis/
```

这一个习惯能挡掉绝大多数「改了 A 忘了 B」的问题。

## 如何使用本目录

1. **动手前**：浏览相关思考指南
2. **过程中**：一旦觉得「有点重复」「有点绕」，回来查
3. **踩坑后**：把新认知写进对应指南（从错误中学习）
