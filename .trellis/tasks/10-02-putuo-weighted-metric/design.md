# 设计：名额加权口径 + 宽表扩容

## 一、计算管线（`工具/build_v3.py`）

```
原始输入
├── data/普陀区/学校/名额到校最低分数线-普陀区-2022-2026.csv   （809 行：年, 校, 高中, 最低分, 来源）
└── data/普陀区/学校/名额到校计划-普陀区-2022-2026.csv          （1719 行：年, 校, 高中, 名额, 来源）

逐年 × 逐线矩阵
  score[c, h, y]、quota[c, h, y]

两条并行链（只有「均分」的加权方式不同，其余步骤完全一致）
  A. 等权（对照） mean_score_base4_eq = 4 区属可得线最低分的算术平均
  B. 加权（主）   mean_score_base4_wq = Σ(score×quota)/Σ(quota)（仅取有分数的线）

  逐年名次（池 = 当年全部有该链数据的初中）
   → P（分位）/ Z（μ,σ）/ ZR（中位, IQR/1.349）
   → 跨年等权聚合（主）＋ 时间权重变体（线性/指数/近 3 年）
   → 三组结构口径（全身 4 所 / 头部 2 所 / 尾部 2 所）各自走同一流程
   → 综合口径 = 三组 P 的等权平均

趋势链（基于**加权**主口径的逐年均分）
  rel_{y} = mean_score_base4_wq − 当年 CORE 中位
  Sen 斜率（Theil-Sen）＋ Spearman(y, rel) → 方向判定
  收敛回归：Δrel ~ rel_2022（n=31）→ b、R²、残差 z
  逐年 IQR / σ / 中位 ±5 分占比
  规模相关性 ρ(quota4_avg, 名次_wq)、ρ(quota4_avg, 名次_eq)

输出（全部覆盖式重写，命名显式）
├── 宽表-初中水平-普陀区-2022-2026.csv          （≈170 列）
├── 趋势分析-普陀区-2022-2026.csv               （主口径=加权）
├── rank-标准化-普陀区-2022-2026.csv            （P_wq/rank_P_wq 主；P_eq/rank_P_eq 对照；Z/ZR 两链）
├── rank-多口径总表-普陀区-2022-2026.csv         （三组 × (eq,wq) + 综合 × (eq,wq) + 时间权重）
└── rank-加权敏感性-普陀区-2022-2026.csv         （加权主口径下的 4 种时间权重）
```

- **单线视角 CSV 不重算**（逐线名次与跨线汇总无关），但报告 3.2 的措辞要注明用的是逐线口径。

## 二、宽表列清单（≈170）

| 组 | 列 | 数量 |
|----|----|------|
| 元数据 | junior_high_school, junior_high_school_code, ownership, years_included, years_list | 5 |
| 原始分数 | score_{code}_{year}（9 高中 × 5 年） | 45 |
| 原始名额 | quota_{code}_{year}（9 高中 × 5 年） | 45 |
| 逐年派生 | mean_score_base4_eq/wq_{year}、rank_base4_eq/wq_{year}、valid_pairs_{year}、quota4_{year} | 25 |
| 逐年标准化 | P/Z/ZR × (eq,wq) × 5 年 | 30 |
| 汇总聚合 | quota4_avg, quota_all_avg, 均名/中位/方差（wq 主）, 三组 P/Z/ZR（wq）, 综合, 名次, 时间权重 8 列 | ≈25 |

## 三、报告更新策略（降低「数字满篇改」的风险）

1. **表格全部由 CSV 生成**（沿用 `assemble_putuo.py` 机制），不手工转写。
2. **正文数字**用「差异清单」驱动：脚本先输出新旧名次/数值差异表（谁升谁降、幅度、
   趋势参数变化），再据清单改写核心结论与个案章；改完用脚本搜检旧数字（如旧名次值）残留。
3. 新增**口径变更声明段**（放核心结论开头）：说明主口径已由等权改为名额加权、
   等权作为对照列并列、以及语义局限（权重来自名额分配，反映规模结构）。

## 四、验证

`validation/verify_v3.py`：
1. 独立实现（排序分组法 + 独立加权求和）复算 `mean_score_base4_wq`、逐年名次、P/Z/ZR、三组、综合；
2. **回归校验**：把新宽表与 git 中的旧宽表按列名求交集，逐值比对（raw 与等权列必须 0 变化）；
3. 报告表按 CSV 全量核对；
4. 新旧名次差异清单（导出 `validation/rank-diff.md`）。

## 五、风险

- **口径变更会改变几乎所有名次**（最大 5 位）：核心结论若只改数字不改判读，会出现「结论与口径不符」，
  必须逐条复核「是否仍成立」；
- 加权链在「某线有名额无分数」时与等权口径的处理必须一致（都跳过该线），否则不可比；
- 宽表列名含中文校名/代码，输出顺序需稳定，便于逐值比对。
